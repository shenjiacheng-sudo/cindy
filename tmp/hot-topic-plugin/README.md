# 热点选题助手：本机体验版 Ghost v3 插件

这是一个 Cindy Ghost v3 插件，不是独立网页 Demo。体验版把多博主画像、本机关键词采集、候选排序和 Agent 创作建议接在同一条插件流程中。

> **仅供当前用户个人非商业学习试跑。请勿商用、转发、上传市场或分发给其他用户。** 本体验版复用本机 MediaCrawler 仓库；该仓库当前许可证为 `NON-COMMERCIAL LEARNING LICENSE 1.1`。超出个人非商业学习范围前，必须先获得许可或更换明确允许该用途的数据源。

## 功能

- 在插件面板新建、切换和删除最多 10 个博主档案；每份档案分别保存账号展示名、平台、赛道、目标粉丝、内容风格、优先/排除关键词、返回数量和排序权重。
- 通过 Cindy 系统目录选择器，让用户亲自选择已有的 MediaCrawler Git 仓库；目录位置保存到该插件的 `/kv`，不保存账号登录资料。
- 用现有 MediaCrawler `.venv` 和已安装的 Chrome 执行一次抖音或快手关键词搜索；仅需要登录时显示扫码窗口，确认登录后关闭并在后台采集。面板按钮可采集并排序；在 Cindy 中输入「热点 抖音」或「热点 快手」时，Agent 也可调用同一采集和排序工具并生成简报。
- 显示作者、展示页链接、可用互动指标、档案匹配分和可尝试的开场/形式/个人化角度。缺少指标显示“不可用”，不估算。
- 原有单份 `/kv` 创作画像会迁移为一份博主档案并保留可识别字段。

## 数据、依赖与安全边界

- 搜索结果是公开关键词搜索候选，不是抖音或快手全站热榜，也不代表平台趋势排名；互动量是采集时的快照。
- 采集仅为搜索模式：不抓评论、不下载视频/图片、不发布、不读取现有 Chrome 登录态，不收集 Cookie/密码。
- 每次运行只把所选仓库 `git archive HEAD` 导出到独立临时目录；不会复制本地未提交的 `config/base_config.py`、`.env`、既有数据或登录状态。JSONL 和临时源码在结束/取消后尽力清理；专用浏览器的原生资料在系统临时目录保留供后续后台搜索复用，系统清理或登录失效时需重新扫码。
- Worker 只返回白名单元数据与对应平台 HTTPS 展示页，过滤播放/下载直链并移除查询串；不会把 MediaCrawler 原始日志传给 Agent 或面板。
- **首次运行不会安装 Python 依赖、Node 包或下载浏览器。** Ghost 规范禁止在安装/首跑时下载可执行代码；本试用包只检查并复用用户已经安装的环境。缺少 Python venv 或 Chrome 时会提示停止，不自动修复。
- `node` 是以当前系统用户权限运行的原生代码，不是受限文件沙箱；`pick` 使系统目录选择器可用。安装时请核对 Cindy 显示的能力，拒绝即无法使用本机采集。插件不声明网络/文件系统/凭证/schedule 宿主槽，但其本机 Python 采集器会直接访问平台公开页面。
- 取消、超时、Cindy 退出时尽力终止 Python 与本次独立 Chrome 进程组；不会主动结束其它 Chrome 或 MediaCrawler 进程。
- 不创建每日任务，不保存持久登录态。本次自动化也不会在后台定时运行。

## 本机环境要求

- macOS；当前体验版仅在 macOS 上验证。
- 用户亲自选择的 MediaCrawler Git 仓库，其 HEAD 源码包含 `pyproject.toml` 与 `NON-COMMERCIAL LEARNING LICENSE`。
- 该仓库已有 `.venv/bin/python`，以及 `/Applications/Google Chrome.app`（或 `/Applications/Chromium.app`）。
- 当前机器此前已检测到 MediaCrawler Python 3.11 venv 与 Chrome。若预检失败，请停止并重新核对本机环境；不要让插件自行安装。

## 1.3.0 入选规则与浏览器复用

最低点赞数由档案设置控制，默认 10,000；缺失不能通过正向点赞门槛。最低博主粉丝量也由档案设置控制，默认 0 表示不限制；设置大于 0 时，粉丝量缺失不能通过。收藏和评论不限。标题或正文必须命中至少两个不同的优先关键词，并有赛道文本依据；作者名称不算命中。校园剧情要求出现校园、学校、教室、同桌等校园场景词。其他赛道去掉剧情、搞笑等泛词后，要求赛道实词均有文本证据。该规则是保守文本筛选，不声称理解视频画面或保证语义正确；工具返回命中词供复核。权重只影响合格视频的排序，不降低门槛；全部淘汰时返回空结果。

浏览器仅复用本插件创建的专用 Chrome，不接管日常 Chrome。普通采集使用无头模式，不显示窗口或标签页；仅登录过期或首次登录时，关闭后台浏览器并以同一原生资料目录打开一个扫码窗口，确认登录后自动关闭并切回后台。二维码只在该网页显示，不另开图片查看器。一次搜索最多尝试一次可见登录，失败时关闭窗口并提示。原生登录资料保留在插件隔离的系统临时目录，系统清理或平台失效后需重新扫码；不保证长期登录。不会把 Cookie 导出到文件、插件界面、模型或插件包。取消采集保留后台浏览器、关闭可见登录窗口，源码和结果每次清理。

## 1.4.0 视频去重与发布时间

排序前按“平台 + 视频 ID”去重，同一视频只保留首次出现的一条原始记录，不混合多个重复记录的指标。抖音与快手相同 ID 不合并；没有 ID 的记录不会按标题误去重。本次结果去重，不跨多次搜索永久隐藏视频。

博主档案新增“视频发布时间”：近一周、近一个月、近一个季度、近半年、近一年、近三年、不限时间。默认近一个月，旧档案没有这一项时同样采用近一个月，其余配置保留。每份档案分别保存范围，Agent 可通过 timeRange 单次覆盖。

枚举依次为 7d、1m、3m、6m、1y、3y、all。一周为向前 7×24 小时；月/季度/半年/年按 UTC 日历向前 1/3/6/12/36 个月，月末自动对齐目标月最后一天。边界时刻包含在内；未来时间不能通过。判断基于视频原始发布时间，不用采集时间替代。支持数字或字符串形式的 Unix 秒/毫秒时间戳及 ISO 日期；无时区的日期文本按 UTC 处理。

启用时间范围时，缺失或无法识别发布时间的视频不入选。不限时间允许无日期视频，但仍需满足点赞、赛道与关键词门槛。界面显示发布日期、重复条数、超出范围条数与时间缺失/无效条数；时间过滤发生在评分之前，过期视频不会影响本批互动分归一化。缺少发布时间的静态示例做排序测试时需显式选择不限时间，不能编造发布日期。

## 1.5.0 按合格结果补足与后台搜索

返回数量 topN 是最终合格视频目标（1–50），不再把候选数量固定为 10。采集器每写入一个不同视频，就等待同一个排序器完成筛选；合格数达到 topN 立即停止后续写入和翻页。多关键词共享视频 ID 去重集合，分页预算在关键词间分配，不重复从第一页补采。最终结果不超过 topN，所有结果仍须满足点赞、赛道、关键词、排除词与发布时间要求。

一轮最多检查 500 个不同候选，并在 12 分钟内结束（含登录时间）。平台结果有限、候选预算/时间用尽或请求失败时，只交付已合格结果，显示目标数、实际数量、缺口与结束原因，不降低门槛凑数。搜索结束不代表平台上没有更多合格内容。调用方传入 videos 时仅分析传入数据，不触发补采。

源码适配只写本轮临时导出的 MediaCrawler 副本，不修改用户原仓库；不新增依赖、不下载浏览器。真实平台登录与连续搜索、Light/Dark 实机显示仍需安装测试包后验收。

## 1.7.0 可调点赞与粉丝门槛

面板新增“关键词最低命中数”，可设置为 1–3，默认 1；同时可调最低点赞数和最低博主粉丝量。视频标题或正文必须命中设置数量的不同关键词；设置为 2 或 3 时，档案必须填写至少同样数量的关键词。
