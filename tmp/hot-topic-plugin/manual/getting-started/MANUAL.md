# 热点选题助手本机体验说明

## 适用范围

这是当前用户个人非商业学习试跑包，不是面向其他用户分发的通用安装版。MediaCrawler 当前仓库采用 `NON-COMMERCIAL LEARNING LICENSE 1.1`；不得商用或转发采集器。插件首次运行不会安装依赖或下载浏览器。

## 首次设置

1. 在 Cindy 插件详情中检查能力清单。此插件需要 `node`（本机运行采集 Worker）和 `pick`（系统目录选择器）；拒绝能力后无法进行本机采集。
2. 打开插件面板，在「博主档案」中填写档案名称、赛道、目标粉丝，选择抖音和/或快手，可填写 1–3 个优先关键词及排除关键词。
3. 点击「选择采集环境」，在系统目录窗口中亲自选择本机已有的 MediaCrawler 仓库根目录。
4. 面板只保存该目录位置，不读取现有 Chrome 登录态。采集器会检查 macOS、MediaCrawler `HEAD` / 许可证、仓库已有 `.venv/bin/python` 与 Chrome。失败时会提示停止；不会运行 `uv sync`、`pip install` 或浏览器下载。
5. 不同账号点击「新增档案」分别设置风格、受众和关键词，再用「当前档案」切换。旧版单份画像会自动迁移为一个档案。

## 运行一轮

选择需要搜索的平台；正常采集在后台进行，仅需要登录时显示扫码窗口。

- 在面板点「采集并排序」可在插件内直接看候选与匹配分。
- 若希望 Agent 进一步写简报，在 Cindy 中输入「热点 抖音」或「热点 快手」。Agent 会通过同一插件工具采集和排序，再根据当前档案整理信号、开场、形式和个人化角度。
- 关键词来自档案的优先关键词；没有填写时以赛道作为搜索词。一次最多 3 个关键词，采集上限受 MediaCrawler 与平台搜索约束。
- 首次登录或登录过期时出现的唯一扫码窗口由你亲自操作，登录后自动关闭。不要把密码、Cookie 或验证码发到聊天。若平台要求额外手机验证，应在浏览器内自行完成。
- 点击「取消采集」可终止当前插件请求并清理临时目录；也可在操作系统中关闭该次独立浏览器。

## 隐私与结果说明

- 每次运行从你所选仓库导出干净的 Git `HEAD` 到唯一系统临时目录，复用原仓库 Python venv，不复制未提交配置、`.env`、账号数据或旧采集结果。
- 搜索模式关闭评论与媒体下载；不会发布内容。
- 临时源码和 JSONL 每次清理。专用浏览器及原生登录资料在独立系统临时目录中保留，按插件安装位置和平台隔离；后续搜索核对身份后复用。扫码窗口关闭后继续复用同一原生资料；系统清理临时目录或登录失效后需扫码。
- 面板只展示作者、视频标题、对应平台 HTTPS 展示页和可用互动指标；播放/下载直链与 URL 查询参数会被过滤。快手数据缺失的收藏/评论会显示“不可用”，不会推算。
- 「本机关键词搜索」不是平台全站热榜，结果及互动量只是采集时快照。创作建议用于研究和差异化表达，不保证传播效果。
- 本体验版不创建每日定时任务、不保存长期登录态、不下载运行时依赖。

## 排序规则

默认权重为互动表现 40%、画像匹配 35%、关键词相关 25%，可在面板调整；权重自动归一化，至少一项需大于 0。互动表现按点赞/收藏相对对数值计算，收藏在同分时优先；不同批次的分数不宜直接横向比较。

显式调用 `load_hot_topic_fixture` 只会读取随包静态示例，不是实时数据。调用 `rank_hot_topics` 时传入非空 `videos` 则分析该数据；省略或传空数组时才运行本机关键词搜索。

## 故障处理

- **未选择目录：** 打开面板使用系统选择器亲自选择仓库根目录。
- **Python venv 缺失：** 本试用插件不会自动安装；请先确认你已有的本机 MediaCrawler 环境，不要让插件写入或覆盖工作区。
- **Chrome 缺失：** 插件不会下载浏览器；需先停止并自行处理本机依赖。
- **仓库或许可证不匹配：** 不要绕过版本/许可证检查。核对来源、`HEAD` 与许可范围。
- **二维码未完成、平台验证失败或超时：** 取消本次运行，待临时数据清理后再试；可复用插件专用原生资料中的登录，不接管日常浏览器。
- **停止、打包或安装器异常：** 不绕过 Cindy 安全启动/安装确认；保留错误并检查本机试用包和隔离开发环境。

## 1.3.0 入选规则与浏览器复用

最低点赞数由档案设置控制，默认 10,000；缺失不能通过正向点赞门槛。最低博主粉丝量也由档案设置控制，默认 0 表示不限制；设置大于 0 时，粉丝量缺失不能通过。收藏和评论不限。标题或正文必须命中至少两个不同的优先关键词，并有赛道文本依据；作者名称不算命中。校园剧情要求出现校园、学校、教室、同桌等校园场景词。其他赛道去掉剧情、搞笑等泛词后，要求赛道实词均有文本证据。该规则是保守文本筛选，不声称理解视频画面或保证语义正确；工具返回命中词供复核。权重只影响合格视频的排序，不降低门槛；全部淘汰时返回空结果。

浏览器仅复用本插件创建的专用 Chrome，不接管日常 Chrome。普通采集使用无头模式，不显示窗口或标签页；仅登录过期或首次登录时，关闭后台浏览器并以同一原生资料目录打开一个扫码窗口，确认登录后自动关闭并切回后台。二维码只在该网页显示，不另开图片查看器。一次搜索最多尝试一次可见登录，失败时关闭窗口并提示。原生登录资料保留在插件隔离的系统临时目录，系统清理或平台失效后需重新扫码；不保证长期登录。不会把 Cookie 导出到文件、插件界面、模型或插件包。取消采集保留后台浏览器、关闭可见登录窗口，源码和结果每次清理。

## 1.4.0 视频去重与发布时间

排序前按“平台 + 视频 ID”去重，同一视频只保留首次出现的一条原始记录，不混合多个重复记录的指标。抖音与快手相同 ID 不合并；没有 ID 的记录不会按标题误去重。本次结果去重，不跨多次搜索永久隐藏视频。

博主档案新增“视频发布时间”：近一周、近一个月、近一个季度、近半年、近一年、近三年、不限时间。默认近一个月，旧档案没有这一项时同样采用近一个月，其余配置保留。每份档案分别保存范围，Agent 可通过 timeRange 单次覆盖。

枚举依次为 7d、1m、3m、6m、1y、3y、all。一周为向前 7×24 小时；月/季度/半年/年按 UTC 日历向前 1/3/6/12/36 个月，月末自动对齐目标月最后一天。边界时刻包含在内；未来时间不能通过。判断基于视频原始发布时间，不用采集时间替代。支持数字或字符串形式的 Unix 秒/毫秒时间戳及 ISO 日期；无时区的日期文本按 UTC 处理。

启用时间范围时，缺失或无法识别发布时间的视频不入选。不限时间允许无日期视频，但仍需满足点赞、赛道与关键词门槛。界面显示发布日期、重复条数、超出范围条数与时间缺失/无效条数；时间过滤发生在评分之前，过期视频不会影响本批互动分归一化。缺少发布时间的静态示例做排序测试时需显式选择不限时间，不能编造发布日期。

## 1.5.0 按合格结果补足与后台搜索

返回数量 topN 是最终合格视频目标（1–50），不再把候选数量固定为 10。采集器每写入一个不同视频，就等待同一个排序器完成筛选；合格数达到 topN 立即停止后续写入和翻页。多关键词共享视频 ID 去重集合，分页预算在关键词间分配，不重复从第一页补采。最终结果不超过 topN，所有结果仍须满足点赞、赛道、关键词、排除词与发布时间要求。

一轮最多检查 500 个不同候选，并在 12 分钟内结束（含登录时间）。平台结果有限、候选预算/时间用尽或请求失败时，只交付已合格结果，显示目标数、实际数量、缺口与结束原因，不降低门槛凑数。搜索结束不代表平台上没有更多合格内容。调用方传入 videos 时仅分析传入数据，不触发补采。

源码适配只写本轮临时导出的 MediaCrawler 副本，不修改用户原仓库；不新增依赖、不下载浏览器。真实平台登录与连续搜索、Light/Dark 实机显示仍需安装测试包后验收。

## 1.7.0 可调点赞与粉丝门槛

在档案中设置关键词最低命中数（1–3，默认 1）、最低点赞数（默认 10,000）和最低博主粉丝量（默认 0 表示不限制）；搜索结果会按这些门槛筛选。
