# 热点选题助手：产品设计与实现约定（本机体验版）

## 用户目标

帮助创作者从抖音、快手的关键词搜索结果中发现可研究的短视频，并基于不同博主档案整理新的创作角度。工具提供候选与比较线索，不承诺播放量或传播结果，也不下载、搬运或发布原视频。

## 体验流程

1. 用户在面板新建/选择博主档案，分别填写账号展示名、平台、赛道、目标粉丝、内容风格、优先/排除关键词、推荐数量和权重。
2. 用户亲自在系统目录选择器中选择已有 MediaCrawler 仓库；只把目录位置保存在插件 `/kv`。面板通过 `/wake` + 同源 `BroadcastChannel` 唤醒逻辑页。
3. 用户点击“采集并排序”，或在 Cindy 中输入「热点 抖音 / 热点 快手」。面板调用和 Agent 工具调用都经过 `main.js` 与同一 Node Worker。
4. Worker 检查仓库根、许可证标记、已有 `.venv/bin/python` 与系统 Chrome；从干净 `git archive HEAD` 建立一次性临时源码副本，不读取工作区未提交文件。
5. Worker 在副本中只连接本插件已验证身份的 Chrome，随机调试端口绑定 127.0.0.1，保留浏览器沙箱。普通搜索无头运行，仅需要登录时切换为可见窗口；不接管日常 Chrome。采集固定为关键词搜索、不开评论、不下载媒体、并发数 1。
6. 用户亲自在独立浏览器扫码登录；Worker 只解析隔离 JSONL 中的白名单字段，按活动档案排序。Agent 工具调用会收到结果并继续生成摘要；面板按钮则直接显示排序列表与模板化思路。
7. 成功、失败或取消后清理本轮源码和结果文件。专用 Chrome 原生资料留在隔离的系统临时目录，后台浏览器跨搜索复用；登录窗口自动关闭。/kv 只保存档案与用户选择的仓库路径。

## 多博主档案状态

```js
{
  schemaVersion: 2,
  activeProfileId: string,
  crawlerRoot: string | null, // 用户在系统 picker 亲自选择的仓库位置
  profiles: [{
    id: string,
    name: string,
    accountName: string,
    platforms: ["douyin" | "kuaishou"],
    niche: string,
    audience: string,
    contentStyle: string,
    includeKeywords: string[],
    excludeKeywords: string[],
    topN: number,
    rankingWeights: { engagement: number, audienceMatch: number, keywordRelevance: number }
  }]
}
```

最多保留 10 个档案。旧版单份画像迁移为一份档案并保留已知字段；档案间不共享创作风格。`crawlerRoot` 属于本机环境，不属于某个博主，也不会被 Agent 参数覆盖。

## 视频数据契约

```js
{
  id: string,
  platform: "douyin" | "kuaishou" | "xhs",
  title: string,
  author: string | null,
  authorUrl: string | null,
  videoUrl: string | null,
  likes: number | null,
  collects: number | null,
  comments: number | null,
  publishedAt: string | null,
  text: string
}
```

本机 adapter 映射抖音 `aweme_id → id`、`aweme_url → videoUrl` 与快手 `video_id → id`、`video_url → videoUrl`；`nickname → author`、`liked_count → likes`、`collected_count → collects`、`comment_count → comments`。只接受来源平台对应的 HTTPS 展示页，并移除 URL 查询串与片段；绝不映射 `video_download_url` 或 `video_play_url`。字段无效或缺失时保持 `null`；快手当前没有提供的收藏/评论指标不可用，不估算。

静态 `data/douyin-snapshot.json` 只供 `load_hot_topic_fixture` 手工检查界面，**本机采集或 Agent 未传非空 videos 时不得静默退回示例数据**。只有明确调用 fixture 工具才读取示例。

## 关键词采集范围与限制

- 本机采集只搜用户档案中的 1–3 个优先关键词；若未填优先词，则以赛道作为一个搜索词。
- 本地 `MediaCrawler` 仅供当前用户个人非商业学习；其仓库许可证为 `NON-COMMERCIAL LEARNING LICENSE 1.1`。体验包不含 MediaCrawler 源码，不得商用或转发。面向他人分发需要另行取得书面授权或改用许可允许的数据源。
- 关键词搜索不是站内全量热点榜；平台搜索排序、可见数据与登录状态可能影响结果。点赞等数据只表示采集时快照。
- 首次运行不会通过 `uv sync`、`pip install`、`npm install` 或浏览器下载补依赖；这是 Ghost 首跑禁止事项。预检失败时提示停止。
- 不自动建立每日自动化；如后续另行增加，创建与费用确认必须由用户在 Cindy 中亲自完成。

## 排序

默认权重：互动表现 `0.40`、画像匹配 `0.35`、关键词相关 `0.25`。输入权重各自限定为 0–1，再归一化；全零或无有效值时回退默认。

- 互动表现：点赞对数归一分占 60%，收藏对数归一分占 40%。
- 画像匹配：赛道与粉丝描述经中英文分词后，在标题、正文及作者字段中计算命中比例。
- 关键词相关：优先词命中比例；任一排除词命中则过滤该视频。
- 综合分按归一化权重求和并四舍五入到 0–100。分数相同时依次按收藏数、点赞数降序；仍相同则维持输入顺序。
- 互动分以本次候选批次内最大对数值作归一化，因此只适合比较同一批次；跨批分数不保证可直接比较。
- 缺失互动指标按 0 参与排序，但 UI 与 Agent 仍看到 `null` /“不可用”，不会补造观测值。

## 创作建议

每条入选内容包含：

- **开场**：围绕主题，为目标粉丝设计具体问题、冲突或结果式开场。
- **形式**：建议改变叙事顺序、场景或演示方式，并结合创作者表达风格。
- **个人化角度**：鼓励加入真实经历、专业判断或可执行清单，而非照搬原视频。

建议用“可以尝试”“建议测试”等语气，不声称一定走红。

## 权限、隐私与运行

- Manifest 如实声明本地 `node` Worker 和 `pick` 系统目录选择能力；不声明 `network`、`fs`、凭证、schedule 或 Library 槽。Node Worker 是系统用户级原生代码，能够联网、读写文件和启动进程；安装者必须信任它。
- `pick` 由 Host 显示系统文件夹窗口；用户亲自选择后才把路径交给 Node Worker。Agent 参数不接收仓库路径。
- 不读取 `.env`、Cookie、密码、账号资料、现有 Chrome 登录状态或工作区未提交文件；不把绝对仓库路径写入日志、工具结果或插件包。
- Python / Git / tar / Chrome 是外部本机进程；使用固定程序与参数数组，不经 Shell 字符串拼接任意命令。取消/停止时终止本次 Python 子进程组并清理源码和结果目录；后台 Chrome 保留供后续搜索，扫码窗口在登录成功、失败或取消后关闭。
- 工具输出、作者名、标题和创作建议均视为不可信文本并转义；外链只允许 HTTPS 平台展示页。

## 明确不在本机体验阶段

- 商业使用、向他人分发 MediaCrawler 采集链、跨平台安装保证。
- 首次自动安装 Python/Node 依赖、下载浏览器、跨浏览器复制 Cookie 或无人值守登录。
- 每日定时采集、后台常驻、全站热榜、评论抓取、媒体下载、内容发布。
- Cindy 服务端修改、自动化创建或模型费用代用户确认。

## 1.3.0 入选规则与浏览器复用

点赞必须达到 10,000（缺失不能通过），收藏和评论不限。标题或正文必须命中至少两个不同的优先关键词，并有赛道文本依据；作者名称不算命中。校园剧情要求出现校园、学校、教室、同桌等校园场景词。其他赛道去掉剧情、搞笑等泛词后，要求赛道实词均有文本证据。该规则是保守文本筛选，不声称理解视频画面或保证语义正确；工具返回命中词供复核。权重只影响合格视频的排序，不降低门槛；全部淘汰时返回空结果。

浏览器仅复用本插件创建的专用 Chrome，不接管日常 Chrome。普通采集使用无头模式，不显示窗口或标签页；仅登录过期或首次登录时，关闭后台浏览器并以同一原生资料目录打开一个扫码窗口，确认登录后自动关闭并切回后台。二维码只在该网页显示，不另开图片查看器。一次搜索最多尝试一次可见登录，失败时关闭窗口并提示。原生登录资料保留在插件隔离的系统临时目录，系统清理或平台失效后需重新扫码；不保证长期登录。不会把 Cookie 导出到文件、插件界面、模型或插件包。取消采集保留后台浏览器、关闭可见登录窗口，源码和结果每次清理。

## 1.4.0 视频去重与发布时间

排序前按“平台 + 视频 ID”去重，同一视频只保留首次出现的一条原始记录，不混合多个重复记录的指标。抖音与快手相同 ID 不合并；没有 ID 的记录不会按标题误去重。本次结果去重，不跨多次搜索永久隐藏视频。

博主档案新增“视频发布时间”：近一周、近一个月、近一个季度、近半年、近一年、近三年、不限时间。默认近一个月，旧档案没有这一项时同样采用近一个月，其余配置保留。每份档案分别保存范围，Agent 可通过 timeRange 单次覆盖。

枚举依次为 7d、1m、3m、6m、1y、3y、all。一周为向前 7×24 小时；月/季度/半年/年按 UTC 日历向前 1/3/6/12/36 个月，月末自动对齐目标月最后一天。边界时刻包含在内；未来时间不能通过。判断基于视频原始发布时间，不用采集时间替代。支持数字或字符串形式的 Unix 秒/毫秒时间戳及 ISO 日期；无时区的日期文本按 UTC 处理。

启用时间范围时，缺失或无法识别发布时间的视频不入选。不限时间允许无日期视频，但仍需满足点赞、赛道与关键词门槛。界面显示发布日期、重复条数、超出范围条数与时间缺失/无效条数；时间过滤发生在评分之前，过期视频不会影响本批互动分归一化。缺少发布时间的静态示例做排序测试时需显式选择不限时间，不能编造发布日期。

## 1.5.0 按合格结果补足与后台搜索

返回数量 topN 是最终合格视频目标（1–50），不再把候选数量固定为 10。采集器每写入一个不同视频，就等待同一个排序器完成筛选；合格数达到 topN 立即停止后续写入和翻页。多关键词共享视频 ID 去重集合，分页预算在关键词间分配，不重复从第一页补采。最终结果不超过 topN，所有结果仍须满足点赞、赛道、关键词、排除词与发布时间要求。

一轮最多检查 500 个不同候选，并在 12 分钟内结束（含登录时间）。平台结果有限、候选预算/时间用尽或请求失败时，只交付已合格结果，显示目标数、实际数量、缺口与结束原因，不降低门槛凑数。搜索结束不代表平台上没有更多合格内容。调用方传入 videos 时仅分析传入数据，不触发补采。

源码适配只写本轮临时导出的 MediaCrawler 副本，不修改用户原仓库；不新增依赖、不下载浏览器。真实平台登录与连续搜索、Light/Dark 实机显示仍需安装测试包后验收。
